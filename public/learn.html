Locate the product boundary

The browser collects a request; the local host validates it. Provider credentials and unrestricted operations stay on the server.

02

Inspect the actual registry

Resolve tutor or support from a real Mastra instance. A registry key, agent id and display name are separate identifiers.

03

Execute a typed operation

A lesson lookup accepts a bounded ID and returns a real catalog record. The tool's description guides use; its schema checks arguments.

04

Separate runtime and Studio

The runtime executes the application. Studio is a development interface for interacting with registered components and inspecting configured evidence.

05

Read the project layout

Follow public, src/server.ts, src/mastra/index.ts and the lesson module. This project layout is one workable organization, not a required monorepo.

06

Review shared contracts

The UI sends a typed JSON envelope, the backend checks it, and the result contains only selected public metadata rather than raw SDK configuration.

Check your understanding

Does opening the architecture lab call a model?

No. Registry inspection and the catalog tool execute locally. The separately labelled live button invokes a model only when configured.

Is a folder layout an access-control boundary?

No. The application must enforce its request schemas, allowed operations and credential boundary in code.

What does Studio replace?

It helps development and inspection. It does not replace the runtime, application tests or authorization.

Implemented scope: The key-free lab really resolves registered agents and executes a Mastra tool. Live generation is optional. No authentication system, vector store or conversation memory is implemented.

Practical exercise

Add a classroom catalog record, rebuild, and inspect it through the existing tool. Explain why the browser does not receive a provider key.
